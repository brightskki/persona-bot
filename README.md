# Persona Telegram Bot

Бот, который заходит в групповой чат, отвечает при тегах/реплаях и редко (раз в 10–20 сообщений) вкидывает контекстную реплику — используя LLM, промпт с личностью и архив реальных сообщений для стиля.

Работает через **webhook** (не polling), поэтому не нужен постоянно работающий сервер — деплоится на Vercel как serverless-функция.

---

## Шаг 1. Создать бота в Telegram

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → следуй инструкциям, получишь `TELEGRAM_BOT_TOKEN`.
2. **Важно:** отключи Privacy Mode, иначе бот будет видеть только сообщения, адресованные ему:
   - `/setprivacy` → выбери своего бота → `Disable`.
3. Запомни username бота (без @) — понадобится в `.env`.

---

## Шаг 2. Завести бесплатный Redis (Upstash)

1. Зайди на [upstash.com](https://upstash.com), зарегистрируйся (можно через GitHub).
2. Создай Redis-базу (Region — любой ближайший, план Free).
3. В настройках базы найди **REST API** → скопируй `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`.

---

## Шаг 3. Получить ключ OpenRouter (LLM)

1. Зарегистрируйся на [openrouter.ai](https://openrouter.ai) → раздел **Keys** → создай ключ.
2. По умолчанию в коде используется бесплатный роутер `openrouter/free` (сам подберёт доступную free-модель).
   Список актуальных бесплатных моделей: https://openrouter.ai/models?max_price=0
   (бесплатные модели иногда меняются/убираются — если модель перестала работать, просто замени в `.env`).

---

## Шаг 4. Настроить персон (мультиперсонный режим)

Бот отвечает от лица нескольких людей из чата. Обычно он помечает персону живой формулировкой вроде «Женя бы написал: …» или «Как говорит Димаш: …», а иногда оставляет чистую реплику, когда из контекста и так понятно, кто говорит.

Есть два способа собрать `config/personas.json`:

### Автоматически — из экспорта Telegram

Если есть экспорт истории чата (Telegram Desktop → настройки чата → Export chat history → формат JSON):

```bash
node scripts/buildPersonas.js /путь/к/result.json
```

Скрипт сам сгруппирует сообщения по отправителям, почистит мусор (короткие "да"/"ок", голые ссылки, простыни) и возьмёт случайную выборку ~40 сообщений на каждого человека — этого достаточно для стиля, не нужно тащить все 12 МБ в промпт.

После этого открой `config/personas.json` и заполни только `systemPrompt` для каждого — личность, характер, манеру речи, отношения с остальными. Примеры сообщений (`archive`) уже будут на месте.

### Вручную

Скопируй `config/personas.example.json` → `config/personas.json` и заполни `systemPrompt` + `archive` (20-40 примеров) на каждого человека сам.

---

Файл `config/personas.json` уже в `.gitignore` — не уйдёт в публичный репозиторий при пуше на GitHub.

**Важно:** если в списке два разных человека с одинаковым отображаемым именем — переименуй одного из них в `personas.json` (например "Женя А" / "Женя Б"), иначе бот будет их путать.

### Связи между персонами (relations)

У каждого персонажа есть поле `relations` — как он относится к остальным, как их называет, какие есть общие темы/подколы:

```json
"relations": {
  "Димаш": "лучший друг с универа, вечно подкалывает за скупость",
  "Ислам": "немного недолюбливает, спорят про футбол"
}
```

Когда бот отвечает от лица персоны и в разговоре упоминается кто-то ещё из списка, соответствующая заметка из `relations` подмешивается в промпт — так ответы учитывают, кто кому кто. Это надо заполнить руками, автоматически из архива сообщений такое не вытащить надёжно.

### Личная песочница и отправка в группу

Сообщения владельца в личке используются для тестов и **не** уходят в группу. Чтобы отправить текст в группу, используй только явную команду:

```text
/send_to_group Привет всем!
```

Для этого задай `OWNER_TELEGRAM_ID`. Рекомендуется также указать `BOT_TELEGRAM_ID`: тогда reply на сообщение бота определяется надёжно, даже если Telegram не передаёт username.

## Шаг 5. Задеплоить на Vercel

```bash
npm i -g vercel
cd persona-bot
npm install
vercel login
vercel
```

После первого деплоя Vercel даст тебе URL вида `https://persona-bot-xxxx.vercel.app`.

Добавь переменные окружения (можно через сайт vercel.com → Settings → Environment Variables, либо через CLI):

```bash
vercel env add TELEGRAM_BOT_TOKEN
vercel env add BOT_USERNAME
vercel env add OPENROUTER_API_KEY
vercel env add UPSTASH_REDIS_REST_URL
vercel env add UPSTASH_REDIS_REST_TOKEN
vercel env add GROUP_CHAT_ID
vercel env add OWNER_TELEGRAM_ID
vercel env add BOT_TELEGRAM_ID
```

После добавления env — передеплой, чтобы они подхватились:

```bash
vercel --prod
```

---

## Шаг 6. Подключить webhook

Локально (или прямо через терминал Vercel) пропиши в `.env` `TELEGRAM_BOT_TOKEN`, затем:

```bash
node scripts/setWebhook.js https://твой-проект.vercel.app/api/webhook
```

Должен прийти ответ `{"ok":true,"result":true,...}`.

---

## Шаг 7. Добавить бота в группу

1. Добавь бота как обычного участника (админ не обязателен, если Privacy Mode отключён через BotFather).
2. Напиши в группе `@username_бота привет` — должен ответить.
3. Чтобы узнать `GROUP_CHAT_ID` — глянь логи в Vercel Dashboard → Functions → Logs после первого сообщения в группе, там будет `chat.id`, либо используй @getidsbot.

## Как это работает

```
Сообщение в группе → Telegram webhook → api/webhook.js
                                            │
                                            ├─ в тексте есть имя одной из персон? → отвечает от её лица сразу
                                            │
                                            ├─ @username бота или реплай на его сообщение? → отвечает сразу
                                            │
                                            └─ иначе, раз в случайные 10–20 сообщений:
                                                  cheap-модель выбирает персону
                                                  → main-модель генерит короткий контекстный ответ
                                                    от первого лица персоны
```

- История последних сообщений и счётчик до следующей самостоятельной реплики хранятся в Upstash Redis. Интервал выбирается случайно в пределах 10–20 обычных сообщений, поэтому бот не вылезает подряд.

## Настройка под себя

### Команды в группе

- `/summary [персона]` — «Прожарка»: ироничная выжимка последних 100 сообщений. Необязательный аргумент выбирает, от чьего лица она написана, например `/summary Женя`.
- `/roast @username [персона]` — точечная дружеская прожарка участника. Например: `/roast @brghtskk Димаш`.

Для максимально персональной прожарки добавь Telegram username в соответствующую персону:

```json
"usernames": ["brghtskk"]
```

Без него команда всё равно работает, но использует только недавние сообщения указанного username, а не профиль и relations.

- `HISTORY_LIMIT` — сколько последних сообщений чата держать в контексте (по умолчанию 100; для `/summary` нужно не меньше 100).
- `AUTONOMOUS_REPLY_MIN_MESSAGES` / `AUTONOMOUS_REPLY_MAX_MESSAGES` — границы случайного интервала самостоятельных реплик (по умолчанию 10 и 20).
- `REACTION_MIN_MESSAGES` / `REACTION_MAX_MESSAGES` — границы интервала реакций (по умолчанию 3 и 7). 🤡 ставится чаще, остальные эмодзи подбираются по контексту.
- `MAX_REPLY_CHARS` — жёсткая максимальная длина ответа (по умолчанию 140 символов, одна строка).
- `CHEAP_MODEL` / `MAIN_MODEL` — можно поставить разные модели: дешёвую для решения "отвечать ли" и более мощную для самой генерации.
- Логика "стоит ли отвечать" — в `lib/llm.js`, функция `decideShouldReply`. Промпт там можно донастроить под характер конкретного персонажа (например, сделать его более/менее болтливым).

## Отладка

- Логи выполнения — в Vercel Dashboard → проект → Functions → Logs.
- Если бот не отвечает вообще — проверь `node scripts/setWebhook.js` вернул `ok:true`, и что Privacy Mode отключён.
- Если отвечает только на теги, но не влезает сам — проверь, что `OPENROUTER_API_KEY` валиден и бесплатная модель ещё доступна (иногда провайдеры убирают free-модели, замени на другую с https://openrouter.ai/models?max_price=0).
